# 确认对话文案规范

模型在需要用户确认的节点上发给用户的内容，**必须是固定文案**。逐字照抄下面的模板，不要自行加句子、加解释、加建议、加 emoji、加「下一步我会……」。

本 skill 有 4 个需要用户回话的节点：

| 节点 | 在哪一步 | 做什么 | 状态 |
|------|----------|--------|------|
| 1. 文章结构确认 | 第 2 步 | 把整理好的文章层级以编号形式发出去，等用户确认 | ✅ 已定稿（本文件） |
| 2. 模板推荐 | 第 3 步 | 推荐 3 套模板 + 告诉用户画廊已打开，等用户挑 | ✅ 已定稿（本文件） |
| 3. 排版方案确认 | 第 4 步 | 把已选模板 + 标题层级映射 + 文章结构再确认一次 | ✅ 已定稿（本文件） |
| 4. 预览确认 | 第 6 步 | 让用户看完预览器后确认可以发布 | ✅ 已定稿（本文件） |

**4 个节点的文案全部已定稿，逐字照抄。** 任何节点都不允许在现场自由发挥。

---

## 通用规则（所有确认节点都适用）

- 一条消息只做一件事：要用户确认，就只发**待确认的内容 + 一个明确的问题**
- 消息发完就停：不预告下一步、不解释方法、不夸文章、不列备选方案、不加 emoji
- 只写**能从文件里数出来**或用户已指定的信息（标题、数量、路径），不写主观评价
- 用户答「可以 / 确认」后直接进下一步；用户指哪条改哪条，改完**只重发这一条消息**，不追加别的
- 编号、路径这类内部格式不要出现在面向用户的消息里，除非模板里就有

---

## 节点 1：文章结构确认（已定稿）

### 模板

```text
**文章结构确认**

文章标题：<标题>

1. <一级标题>
1.1 <二级标题>
2. <一级标题>

包含 <N> 张图片。

确认这个结构吗？要调整的地方直接说。
```

固定成分只有：开头行 `**文章结构确认**`、`文章标题：` 行、编号结构、`包含 <N> 张图片。`、结尾问句。中间不留别的段落。

### 编号规则

| 原文 | 编号 |
|------|------|
| `#` | `1.` / `2.` / `3.` |
| `##` | `1.1` / `1.2` |
| `###` | `1.1.1` |

- 编号只是**给用户看的结构索引**，不是把正文标题改成数字 —— 正文里标题文字原样保留，`structured.md` 里该是 `#` 还是 `##` 都不变
- 按原文出现顺序编号，没有二级标题就不出现 `x.1` 行
- `<N>` = 正文图片总数（wikilink 与 markdown 两种写法都算）；一张都没有时写 `包含 0 张图片。`

### 三种来源情形

| 原文情况 | 做法 |
|----------|------|
| 层级清晰、层级一致 | 直接把原文标题层级翻译成编号 |
| 层级混乱（如拿 `#` 当总标题、层级不统一） | 归一成一致的层级后列出；段落文字不动 |
| 完全没有标题（纯段落长文） | 读完全文，总结出一套合理的 h1/h2/h3 后列出；段落文字不动 |

模型新拟或调整过的标题**照常列出，不加任何标记**（不写「新」「调整」），也不要在消息里解释为什么调。

### 消息里不能出现的东西

- 「第 N 次确认」「1/3」这类进度说明
- 结构调整的解释（如「模板最强样式在 `#` 上，所以把 `##` 提升了」）
- 对文章的评价、风格建议、排版建议
- 下一步要做什么（画廊、渲染、校验……）
- 正文段落内容、章节摘要、字数统计
- 样式丰富化与图片注释的信息（给重点句加格式、逐张看图写图注，这些只在梳理结构时同步完成、
  写进 `structured.md`，**消息内容与没有这两件事时完全一样**，不要提）

### 示例 A：原文层级清晰

原文（`#` 是章节、`##` 是小节，另有 3 张图）：

```text
**文章结构确认**

文章标题：一个人如何把复杂的项目讲清楚

1. 先说结论，别铺垫太久
1.1 结论不是标题
1.2 一句话说完重点
2. 结构的三种排法
3. 收尾要留一个动作

包含 3 张图片。

确认这个结构吗？要调整的地方直接说。
```

### 示例 B：原文一个标题都没有

原文是 4 段纯文字（无任何标题），模型读完总结出层级，段落文字一个字不动：

```text
**文章结构确认**

文章标题：为什么你的文章读起来累

1. 读者到底是怎么读的
1.1 注意力是碎片化的
2. 节奏单一让人抓不住重点
3. 三个动作让重点自己跳出来

包含 0 张图片。

确认这个结构吗？要调整的地方直接说。
```

### 用户确认之后

把文章标题写进 `02-structured/structured.md` 的 frontmatter，正文按确认后的层级写入：

```markdown
---
title: "为什么你的文章读起来累"
---

# 读者到底是怎么读的

（原文段落，一字未改）

## 注意力是碎片化的

（原文段落，一字未改）
```

- 标题只进 frontmatter，**不进正文**
- 正文从第一个 `#` 章节标题开始
- 段落文字、图片位置、引用块全部保持原样；只允许改标题的层级与文字
- 这份文件是后续所有步骤的唯一真相源，内容一致性校验也以它为准

## 节点 2：模板推荐（已定稿）

画廊页生成并打开之后，紧跟着发这条消息。

### 模板

```text
**模板推荐**

按这篇内容，我挑了 3 套：

1. <模板名>（最推荐）— <风格特征>
2. <模板名> — <风格特征>
3. <模板名> — <风格特征>

画廊已经为你打开了，点画廊底部的「复制模板名」，把名称发给我。
```

固定成分只有：开头行 `**模板推荐**`、`按这篇内容，我挑了 3 套：`、三条推荐、结尾那句。中间不留别的段落。

### 填充规则

- **必须正好 3 套**，第 1 条是最推荐的那套，后面跟 `（最推荐）`
- `<风格特征>` 用预设自己的 `tagline` 原文（用 `node -e "const {PRESETS}=require('./scripts/presets/index');for(const p of Object.values(PRESETS))console.log(p.name, '=>', p.tagline)"` 取，或看包内 `manifest.json`），**不要自己另写描述**，也不要加“为什么适合你这篇”这类分析
- 3 套尽量风格差异大（章节框 / 极简 / 徽章 之类），最好来自不同分类，方便用户一眼分清
- 用户直接点名了预设（如“用极简雅致”）时不发这条消息，直接进第 4 步

### 消息里不能出现的东西

- 模板总数、「分类里还有 N 套」、画廊分类/推荐位介绍、手机版/电脑版说明
- 预设 ID（`purple-badge` 这种）、文件路径、命令
- 对文章的评价、排版建议、下一步要做什么
- 结构回顾（第 2 步已经确认过了，不重复）

### 示例

```text
**模板推荐**

按这篇内容，我挑了 3 套：

1. 极简雅致（最推荐）— 灰白极简风格，双圆点标题装饰，大行距两端对齐，雅致克制
2. 公众号蓝黄线框 — 浅蓝灰底 + 章节独立框 + 蓝黄标签
3. 童趣手绘 — 动态标题占位符 + 手绘数字 1～10 + 可替换顶部插画

画廊已经为你打开了，点画廊底部的「复制模板名」，把名称发给我。
```

> 示例里的风格特征就是 `tagline` 原文，不要自己缩短或润色 —— 截短也属于改写。

### 用户回话之后

用户会把模板名（如「极简雅致」）粘回来 —— 他可能选推荐位里的，也可能在画廊里按分类翻到任意一套：

```bash
node -e "const {PRESETS}=require('./scripts/presets/index');for(const p of Object.values(PRESETS))console.log(p.name, '=>', p.id, '['+p.categoryName+']')"
```

把名称映射回预设 ID 后进第 4 步（节点 3 排版方案确认）。用户都不满意时，换一批预设重新生成画廊，并重发这一条消息。

## 节点 3：排版方案确认（已定稿）

用户选完模板之后、开始渲染之前发这条消息 —— 把「已确认的模板 + 标题层级 + 文章结构」摆在一起做最后一次核对。

### 模板

```text
**排版方案确认**

模板：<模板名> — <风格特征>

标题层级：<标题层级说明>

文章结构：
<编号结构>

确认就开始排版，要调整的地方直接说。
```

固定成分：开头行 `**排版方案确认**`、模板行、标题层级行、`文章结构：` + 编号块、结尾问句。中间不留别的段落。

### 填充规则

- `<模板名>`：中文名即可，**不写预设 ID**（`elegant-minimal` 这类）
- `<风格特征>`：预设自己的 `tagline` 原文，跟节点 2 一致，不要改写也不要截短
- **文章结构跟第 2 步发出去的那份逐字一致** —— 同一套编号，不重新编号、不改标题文字
- `<标题层级说明>` 按 heading-offset 取值写大白话，**不要写 `heading-offset = 0` 这种实现细节**：

| heading-offset | 消息里写 | 什么时候用 |
|----------------|----------|------------|
| 0（默认） | `不调整（# 套用模板的主标题样式）` | 文章的 `#` 就是章节标题 |
| -1 | `升一级（## 套用模板的主标题样式）` | 文章主要章节用的是 `##`，`#` 被占作标题层 |
| +1（少见） | `降一级（# 用二级样式，## 用三级样式）` | 需要给 `#` 让出标题层 |

### 消息里不能出现的东西

- 预设 ID、heading-offset 数值、文件路径、命令
- 文章标题、图片数量（节点 1 已经确认过，不重复）
- 其他备选模板、对文章的评价、排版建议、下一步要做什么

### 示例（用户选了「极简雅致」）

```text
**排版方案确认**

模板：极简雅致 — 灰白极简风格，双圆点标题装饰，大行距两端对齐，雅致克制

标题层级：不调整（# 套用模板的主标题样式）

文章结构：
1. 排版是在为阅读铺路
2. 从混乱草稿到清晰表达

确认就开始排版，要调整的地方直接说。
```

### 用户回话之后

用户确认后，把预设 ID 与 heading-offset 写进 `03-style/selected-preset.json`，进第 5 步（渲染 + 校验）。

用户要求在这里改结构时：改完 `02-structured/structured.md`，**重发这一条消息**再确认，不要只改文件不吭声。

---

## 节点 4：预览确认（已定稿）

校验门通过、预览器已在浏览器里打开之后发这条消息。

用户提出修改时：回第 5 步重新渲染 + 跑校验 → 重开预览器 → **重发同一条消息**，不要临场造句。

### 模板

```text
**预览确认**

预览器已经打开了，切一下「手机端」和「夜间」都看看。

没问题就点右上角「复制到公众号」，粘进公众号编辑器就行；要改的地方直接说。
```

这条消息**逐字使用**，不改写、不拆分、不加句。

### 规则

- 按钮文案跟预览器界面保持一致：`手机端`（顶部左侧的切换）、`夜间`（右上角的切换）、`复制到公众号`（右上角主按钮）
- 用户明确说「可以 / 确认 / 没问题 / 发吧」才算走完这一步
- 用户提出修改 → 重新渲染 + 校验 + 重开预览器 → 重发这条消息

### 消息里不能出现的东西

- 校验结果（`校验门: 3/3 通过` 这类）、文件路径、命令、预设 ID
- 「图片会自动转存 / 不需要图床 / 不需要传图」这类机制说明
- 复制内容与日夜/端模式无关这类的实现细节（预览器侧栏已经写了）
- 文章结构、模板信息的回顾（前面的节点已经确认过）
- 快捷键（<kbd>D</kbd> / <kbd>M</kbd>）、预览器底部的其他提示、后续步骤

### 示例

```text
**预览确认**

预览器已经打开了，切一下「手机端」和「夜间」都看看。

没问题就点右上角「复制到公众号」，粘进公众号编辑器就行；要改的地方直接说。
```
