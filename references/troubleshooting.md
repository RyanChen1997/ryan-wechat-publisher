# 常见问题与避坑指南

## 发布 API 常见错误码

| errcode | 含义 | 解决方法 |
|---------|------|---------|
| 40164 | invalid ip | host 直连被拒绝。必须通过云托管服务调用，确认 WECHAT_PUBLISHER_URL 是云托管公网域名 |
| 45001 | media size out | 图片太大，单图 ≤ 10MB |
| 45004 | description too long | digest 超过 120 字符，截断或缩短 |
| 45009 | daily quota exceeded | 当日 API 调用配额用完了，明天再试 |
| 48001 | api unauthorized | 云托管环境是小程序的不是公众号的，去控制台确认云托管环境身份；或者微信令牌权限没配 |

## 连接错误

如果调用时出现 `ConnectionError`、`Connection refused`、timeout 或 HTTP 5xx：

1. **先自动重试探测**：微信云托管冷启动/短暂抖动很常见，先主动探测服务是否恢复
   - 间隔 10 秒请求一次 `${WECHAT_PUBLISHER_URL}/health`
   - 最多重试 5 次（约 50 秒）
   - 任一返回 200 即视为恢复，立即继续发布流程
2. 5 次都失败，再提示用户 `WECHAT_PUBLISHER_URL` 可能失效了
3. 让用户去微信云托管控制台确认公网 URL 是否有变化
4. 用户提供新 URL 后，帮用户重新 `export WECHAT_PUBLISHER_URL=<new-url>`

## 排版常见问题

### 段落间距太宽 / 太窄

- 检查模板用的是**空行法**还是 **margin 法**
- 空行法：段落之间有 `<p><br></p>` 空段落
- margin 法：段落自身带 `margin-bottom`，中间没有空行
- 两种混用会导致间距加倍，必须和模板一致

### 标题样式没出来（只有普通文字）

大概率是**标题层级错配**：
- 模板最强样式在 h1，但文章用的是 `##`（h2）
- 解决：加 `--heading-offset -1` 整体升一级
- 参考 SKILL.md 第 4 步的"标题层级映射"说明

### 图片不显示

发布版 HTML 用 `data-src`（微信懒加载规范），在普通浏览器里看图片是空白的，属正常现象。
预览版（article-preview.html）才用 `src` 真实显示图片。

上传到公众号后，微信编辑器会自动识别 `data-src` 并显示。

### SVG 里的中文字体不一致

标题文字不要写在 SVG `<text>` 里，用 HTML 文字 + CSS 实现标题，SVG 只做装饰背景。
如果必须放 SVG 里，字体栈要写全：`'PingFang SC', 'Microsoft YaHei', sans-serif`

### SVG 装饰图在公众号不显示

公众号不支持 inline SVG 和 base64 SVG 图片，会被过滤或不渲染。

**正确做法**：SVG 转 PNG，作为普通图片通过 `data-src` 走上传流水线。
- 工具：`scripts/utils/svg-to-png.js` 中的 `DecoAssetManager`
- 渲染：`decoAssets.get(svgString, name, width)` 拿到图片路径
- 详见 `references/clone-guide.md` 「装饰图实现规范」

### 列表圆点样式错乱（变成逗号/两个点）

用 `<ul>/<li>` + `position: absolute` 自定义圆点时，公众号会同时显示默认列表符号，导致叠加错乱。

**正确做法**：完全不用 `<ul>/<ol>/<li>` 标签，改用 `<section>` + 内联文字圆点（`•` `◆` `✦` 等 Unicode 字符）实现列表。
所有内置预设已改为这种写法，新增预设照此规范。

### 全局计数器不重置

如果多次渲染后标题编号（如徽章数字）不从 1 开始，检查每次调用渲染函数时计数器是否重置。
base.js 的 `renderMarkdown` 函数每次调用时 `h1Counter = 0` 会重置，如果自定义 preset 的装饰函数有自己的计数器，也要确保每次渲染前重置。

## 复刻常见问题

### 只看当前元素样式，不看继承

基础样式（字号、颜色、行高）往往在外层祖先上，必须合并完整祖先链的样式。
用 `getInheritedStyle(el)` 函数递归合并。

### 找错装饰图

正文配图和装饰图尺寸接近时容易混淆。判断方法：
- 紧挨着标题文字的才是标题装饰
- 特别小的图片（宽 < 100px）通常是图标/符号
- ratio < 0.1 的扁图片通常是分割线

### 试图 1:1 还原复杂插画装饰

手绘/插画风模板的装饰元素非常定制化，花大量时间画 SVG 仍难以还原。
**正确做法**：抓设计语言（配色体系、构图方式、元素类型），做同风格简化版，不追求像素级一致。投入产出比更高。

### 忽略整体页面结构

只盯着标题、正文、图片等内容元素，漏掉了整体背景色、外框装饰、边距等宏观特征。
**分析模板从外到内**：先看最外层的背景/边框/边距，再往里看内容块，最后才看单个文字样式。
宏观特征对风格辨识度的影响远大于细节。

## 其他避坑要点

1. **digest ≤ 120 字符**：否则 `errcode 45004`
2. **云托管环境必须是公众号身份**：小程序云托管会报 `48001 api unauthorized`
3. **外部图片必须上传到微信**：非微信域名的图片在公众号里会被过滤成空白
4. **不要用 position: fixed**：公众号内会出问题
5. **不要用 `<style>` 标签或 class**：公众号会过滤，所有样式必须是内联 style
